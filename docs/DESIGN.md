# DESIGN.md — 무엇을 만드는가

## 한 줄 요약

모바일 브라우저에서 바로 실행되는 3D 궁수 아레나 게임.
경험치 코어를 모아 레벨업하고 3중 1택으로 강해지며,
혼자(봇 상대)도 여럿(실시간 멀티)도 즐길 수 있다.

## 누가 쓰는가

- **대상**: 쉬는 시간에 짧게 즐길 거리를 찾는 사람. 게임에 익숙하지 않아도 됨.
- **상황**: 회사·학교에서 5분 남았을 때. 설치도 로그인도 없이 링크만 열면 시작.
- **기기**: **모바일 브라우저가 최우선.** 데스크톱은 그 다음.
  성능·조작·화면 구성의 모든 판단 기준은 "중급 사양 스마트폰"이다.
- **한 판 길이**: 3~5분. 언제 죽어도 손해가 없어야 한다.

## 핵심 기능 (우선순위 순)

<!-- 루프는 위에서부터 하나씩 완성한다. 순서를 건너뛰지 말 것. -->

### A. 오프라인 코어 (혼자서도 재밌는 게임 만들기)

1. **3D 아레나 + 이동 + 조준 + 자동 발사**
   - 쿼터뷰(비스듬히 내려다보는) 3D 카메라. 1인칭·정탑다운 둘 다 아니다.
   - 조작은 **처음부터 터치와 키보드를 함께** 만든다.
     나중에 얹으면 화면 구성을 다시 짜야 한다.
     - 모바일: 왼쪽 가상 스틱으로 이동, 오른쪽 가상 스틱으로 조준.
       오른쪽 스틱을 건드리지 않으면 **가장 가까운 적을 자동 조준**한다.
       (한 손으로도 플레이 가능해야 한다)
     - 데스크톱: WASD 이동, 마우스 방향 조준
   - 조준 방향으로 **자동 발사**(버튼 불필요). 화살은 날아가는 투사체.

2. **모바일 기준선 확보** — 아래를 만족하지 못하면 다음 항목으로 넘어가지 않는다.
   가로 화면 대응, 안전 영역(노치) 회피, 터치 반응 지연 없음,
   중급 스마트폰에서 목표 프레임 유지. 이 기준선은 이후 모든 바퀴에서 유지된다.

3. **경험치 코어 + 레벨업** — 코어를 먹으면 경험치바가 차고, 다 차면 1레벨업.
   코어는 두 곳에서 나온다:
   - 맵에 흩어져 있고 시간이 지나면 다시 생성 (소량)
   - **적을 처치하면 드롭 (다량)**
   - **적을 잡는 쪽이 확실히 빠르게 성장하도록 비율을 잡는다.**
     코어만 주우며 전투를 피하는 것이 최적해가 되면 안 된다.

4. **3중 1택 업그레이드** — 레벨업 때마다 카드 3장 제시, 1장 선택. 그동안 게임은 멈춘다.

5. **적 봇 + 전투** — 봇이 플레이어를 추적하고 화살을 쏜다. 피격·체력·사망 처리.

6. **사망 · 리스폰 · 부활**
   - **리스폰(무료)**: 레벨과 업그레이드가 **전부 초기화**되고 처음부터 시작.
   - **부활(광고)**: 죽은 그 자리에서 **레벨과 업그레이드를 유지한 채** 이어서 진행.
   - 실제 광고 연동 전까지는 더미 화면으로 흐름만 완성해 둔다.

7. **결과 화면 + 기록 저장** — 도달 레벨, 처치 수, 생존 시간.
   최고 기록은 브라우저에 저장.

### B. 살 붙이기 (루프가 오래 돌 수 있는 구간)

8. **업그레이드 확장** — 관통, 다중 발사, 튕김, 이동속도, 회복 등.
   한 바퀴에 하나씩 추가하고 밸런스를 확인한다.
9. **적 종류 확장** — 돌진형, 원거리형, 방패형 등. 한 바퀴에 하나씩.
10. **맵 추가** — 지형과 장애물이 다른 아레나. 시작 시 선택.

### C. 수익 구조

11. **리워드 광고 연동** — 6번에서 만든 부활 흐름에 실제 광고를 붙인다.
12. **배포** — 정적 호스팅에 올리고 **실제 스마트폰에서** 확인한다.

### D. 온라인 멀티플레이 (여기부터는 사용자 확인이 필수)

13. **권위 서버 + 실시간 동기화** — 서버가 정답을 갖고,
    클라이언트는 예측하고 보정한다. 같은 아레나에 여러 명.
14. **봇 필러** — 접속자가 적으면 정해진 비율만큼 봇으로 채운다.
    빈 방에 혼자 들어가는 상황을 만들지 않는다.
15. **온라인 사망 규칙** — 온라인은 죽으면 게임 종료.
    광고를 보면 그 자리에서 1회 부활(이어하기).

## 하지 않을 것

<!-- 범위를 명확히 해야 루프가 옆길로 새지 않는다 -->

- **A 구간이 끝나기 전에 멀티플레이에 손대지 않는다.** 혼자서 재미없는 게임은
  사람이 모여도 재미없다. 순서를 지키는 것이 이 프로젝트의 핵심 전제다.
- **모바일에서 안 돌아가면 완료가 아니다.** 데스크톱에서만 되는 기능은 만들지 않는다.
- **로우폴리 프리미티브를 벗어나지 않는다.** 외부 3D 모델·텍스처·실사풍 그래픽 금지.
  기본 도형(박스·구·원기둥·원뿔)과 색·조명·이펙트로만 표현한다.
- **물리 엔진을 도입하지 않는다.** 평평한 아레나이므로 충돌은 수평면 원-원 판정으로
  충분하다. 직접 구현한다.
- **1인칭 시점을 만들지 않는다.** 쿼터뷰 고정.
- **원작 모방 금지** — arrow.io, 궁수의 전설(Archero) 등 기존 게임의
  이미지·사운드·코드·이름·UI 배치를 가져오지 않는다. 규칙과 장르 관습은
  자유롭게 참고하되, 화면을 나란히 놓고 비교했을 때
  "같은 게임"으로 보이면 안 된다. 이름에 arrow·archer 계열을 쓰지 않는다.
- 계정·로그인 시스템
- 인앱결제, 유료 재화, 스킨 상점
- 길드·친구·채팅
- 시즌제, 배틀패스, 일일 출석
- 모바일 네이티브 앱 출시 (웹만)
- 맵 에디터
- 전 세계 랭킹 서버 (D 구간까지 끝난 뒤에 다시 판단)

## 기술 스택

- **언어/프레임워크**: TypeScript + Three.js (WebGL). 게임 엔진은 쓰지 않는다.
  의존성이 적을수록 루프가 코드 전체를 파악하기 쉽다.
- **빌드**: Vite
- **저장 방식**: 브라우저 localStorage (최고 기록·설정).
  서버 저장은 D 구간 전까지 하지 않는다.
- **실행 환경**: 모바일 브라우저 우선(iOS 사파리 · 안드로이드 크롬),
  데스크톱 브라우저는 그 다음.
- **서버 (D 구간)**: Node.js + WebSocket(ws). 체감 지연이 문제가 되면
  WebRTC 데이터채널로 교체를 검토한다.
- **그래픽**: **로우폴리 프리미티브.** 외부 모델·텍스처 파일을 쓰지 않고
  Three.js 기본 지오메트리(박스·구·원기둥·원뿔)와 색·조명·이펙트로만 표현한다.
  이유: (1) 루프가 코드만으로 전부 만들 수 있고, (2) 저작권 문제가 없으며,
  (3) 다운로드할 에셋이 없어 모바일 로딩과 성능에 유리하다.
  나중에 교체할 수 있게 모델 생성 코드는 한곳에 모아 둔다.
  **실제 모델·이미지로의 교체는 A 구간(1~7번)이 끝나고 재미가 확인된 뒤에
  검토한다. 그 전에는 외부 에셋을 도입하지 않는다.** 도형 상태에서 재미없는
  게임은 그림을 입혀도 재미없고, 에셋에 묶이면 루프가 멈춘다.

## 화면/구조 개요

**화면 흐름**

```
타이틀 → 모드 선택(오프라인 / 온라인) → 맵 선택 → 게임 화면 → 결과 화면
                                                      ↑            │
                                                      └── 다시하기 ─┘
```

**게임 화면 구성 (가로 화면 기준)**: 화면 전체가 3D 아레나.
좌하단에 이동 스틱, 우하단에 조준 스틱, 상단에 체력바·경험치바·레벨,
그 옆에 처치 수와 생존 시간. 레벨업 시 화면 중앙에 카드 3장이 뜨고 게임이 멈춘다.
엄지손가락이 가리는 영역에는 정보를 두지 않는다.

**모듈 구성**

- `core/` — 게임 루프, 상태 관리, 시간 처리
- `entities/` — 플레이어, 적, 화살, 경험치 코어
- `systems/` — 이동, 충돌(수평면 원-원), 전투, 레벨/경험치, 업그레이드, 자동 조준
- `render/` — Three.js 씬·카메라·조명, 프리미티브 모델 생성
  (나중에 교체할 수 있게 분리)
- `input/` — 터치(가상 스틱)와 키보드·마우스를 같은 인터페이스로 처리
- `ui/` — 타이틀, 맵 선택, HUD, 업그레이드 카드, 결과 화면
- `data/` — 업그레이드 목록, 적 정의, 맵 정의 (코드가 아닌 데이터로 분리해서
  새 콘텐츠 추가가 파일 한 곳 수정으로 끝나게 한다)
- `net/` — D 구간에서 추가. 그 전까지 만들지 않는다.

## 품질 기준

- 다른 사람이 봤을 때도 퀄리티가 떨어지지 않을 것
- **모바일 브라우저에서 링크를 열고 3초 안에 플레이가 시작될 것**
- **중급 스마트폰에서 적 20마리·투사체 60개 상황에 60fps를 유지할 것**
  (달성이 어려우면 30fps로 목표를 낮추되, 프레임이 튀지 않는 쪽을 우선한다)
- **한 손으로도 플레이가 가능할 것**
- **한 판이 3~5분 안에 끝날 것.** 이보다 길어지면 쉬는 시간용이 아니다
- **처음 하는 사람이 설명 없이 30초 안에 조작을 이해할 것**
- 터치 입력과 화면 반응 사이에 체감되는 지연이 없을 것
- 게임 중 어떤 상황에서도 콘솔에 에러가 찍히지 않을 것
